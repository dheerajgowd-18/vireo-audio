Methodology & Data Quality

Complete transparency regarding data provenance, mathematical integrity, and technical boundaries.

Data Integrity & Referential Completeness
Processed 11,750 support tickets, 44 agents, 15,500 orders, 9,500 customers, and 14 products. Verified 0 primary key duplicates and 0 foreign key orphans across all tables. Order IDs directly populated in 7,643 tickets (0 unmatched). Identified 1,388 multi-order pairs to completely prevent Cartesian fan-out errors.
Timestamp Offset Reconciliation (+05:30 IST)
Diagnosed legacy Freshdesk ingestion flaw affecting 2,309 tickets where resolved timestamps lacked timezone metadata, creating negative handle times. Reconciled via derived resolved_at_reporting = resolved_at + 05:30 while strictly preserving raw timestamps in source data.
Customer Satisfaction (CSAT) Measurement Protocol
Evaluated 5,196 survey responses (44.22% response rate). In strict compliance with operating standards, blanks were excluded from the denominator and never imputed as zero or group averages, preventing artificial performance deflation.
AI & Machine Learning Governance
Implemented a 100% local TF-IDF + Logistic Regression architecture with deterministic rule overrides. Zero external cloud API calls executed (₹0 paid model cost; ₹58,750 hypothetical external API benchmark at ₹5/ticket). Generalization verified via held-out 5-fold stratified cross-validation (55.56% ML accuracy, 65.56% hybrid accuracy) against rule-assisted pseudo-labels.
Documented System Limitations
1. Benchmark annotations are rule-assisted pseudo-labels; human double-blind labels should be gathered for production deployment.
2. The hardware defect detector's 100% benchmark precision is an internal self-consistency check against deterministic regex pseudo-labels, capturing overt defect phrases with zero heuristic false alarms but 47.06% recall; colloquial phrasing requires human technical triage.
3. Operational correlation between defect signals and low CSAT does not establish legal or physical manufacturing causality without hardware teardown testing.
4. Rare classes (cancellation N=3, product_enquiry_setup N=4 in sample) exhibit high variance across cross-validation folds and rely on rule overrides.
